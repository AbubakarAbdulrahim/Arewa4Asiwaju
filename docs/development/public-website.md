# Public website implementation

## Routes

The English public routes are `/`, `/about`, `/mission`, `/leadership`, `/news`, `/news/[slug]`, `/events`, `/events/[slug]`, `/faqs`, `/contact`, `/privacy`, and `/terms`. Existing registration and card verification routes remain available. Hausa pages currently exist at `/ha` and `/ha/about`; the typed dictionaries are in `src/messages/` and provide the structure for continuing approved translation.

## Content sources and publication

Mission and organisation descriptions are based on the strategic blueprint supplied for this project. Names from the blueprint are not shown as current leaders until the organisation confirms the roster. No statistics, testimonials, event dates, contact details, or government outcome claims have been invented.

News and events are queried from the `announcements` and `events` tables using the Supabase public anon key. Queries select only fields needed by public pages and always filter `is_published = true`; the RLS policies are defined in the Phase 3 migration, and `20261010000001_public_content_column_grants.sql` narrows direct API access to approved fields (with event joining links and internal counters excluded). Content is server-rendered and React escapes text fields. If Supabase is not configured, the pages show a setup state; if a query fails, they show a temporary unavailability state; if there are no approved rows, they show an empty state. Apply and verify both migrations before configuring public publishing in a deployment.

The event listing filters past events at request time. Published content is request-time rendered using Next.js `connection()` so publication changes do not require a site rebuild. Keep event and article body content as plain text unless a reviewed, sanitizing rich-text renderer is introduced.

## Legal and contact pages

The privacy and terms routes are explicitly marked as drafts and excluded from search indexing. They do not constitute legal approval. The privacy notice needs the organisation's legal controller details, purpose and lawful-basis assessment, retention schedule, processor inventory, contact channel, and incident process. The contact page does not fabricate channels and explains that verified contact information is pending.

## SEO and accessibility

The root layout provides a metadata base, site description, Open Graph defaults, and a skip link. Public routes define their own title and canonical path; the sitemap and robots routes are generated by Next.js. The sticky header collapses into a labelled menu below the wide-screen breakpoint; it exposes expanded state and closes on Escape. FAQ disclosure uses native `details` and `summary` elements. The logo is the supplied movement identity asset; no stock or unapproved campaign imagery was added.

## Review limits

Build, lint, TypeScript, formatting, unit tests, and local HTTP route checks were run for this phase. A graphical browser was not available in this environment, so mobile viewport behavior and screen-reader behavior still need a visual/manual pass. Real-user Core Web Vitals are not measurable until a deployed site has sufficient traffic. Database-backed populated content remains contingent on Phase 3 and public-content grant migrations being applied and approved content being entered through the CMS/admin workflow.
